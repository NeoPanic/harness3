# 运行中的动态委派与原 Agent 续作

Agent 可以在执行任务时按批准角色提出子任务。控制面预留容量、创建独立实例和会话，等待当前 Run 成功结算后展开依赖图；子任务全部完成后，原实例以新 Run 接收贡献并继续完成原任务。子 Agent 也可在同一授权范围内继续委派。

## 从 Web 体验

1. 打开“自主调研”，选择 `demo-delegator@1.0.0`（离线确定性演示）或 `research-delegator@1.0.0`（OpenAI Responses）。
2. 展开“动态委派”，启用后选择深度、单次子任务数、每个研究任务的后代总数，并勾选批准的角色母体。角色可使用不同模型、插件和实例参数。
3. 发起任务。初始规划仍创建 2–6 位研究者和独立汇总；研究者可在执行期间继续派生。真实模型根据任务需要决定是否分工，勾选授权不保证每次都会委派。
4. 在任务卡片查看委派来源、子任务标题与状态、续作要求和原始 Run。执行尝试台账将“委派规划”与最终贡献区分开。只有原任务续作成功，下游汇总才会执行。

“协作目标”创建表单也可逐任务启用相同策略。使用的主实例和所有候选都必须绑定 `platform.delegation@1.0.0`。普通单实例 Run 不会自动创建团队。新的默认母体不会修改已有不可变版本。

## 身份、资源与执行规则

- `platform.delegation.read` 返回当前任务的角色声明、深度和剩余任务额度。`platform.delegation.submit` 只接受角色名、子任务指令与续作要求。Goal、父任务、来源实例、来源 Run 均由宿主确定，模型不能伪造身份或传入任意母体。
- 操作者固定角色的 Preset 版本及参数；平台在目标创建时校验，在实际预留时再次实例化。角色权限来自明确批准的母体，尚无自动的权限交集计算或 Principal/Grant。
- 深度上限 1–3；一次最多 1–4 项；每个授权根任务最多 1–12 个后代；整个 Goal 的已有任务与未展开预留合计最多 16 项。共享全局 64 个实例/容量预留和 4 个本地 Worker 槽位。任务额度限制规模，不代表费用预算。
- 每个 WorkItem 只允许一份不可变委派计划。按来源 Run 去重，相同内容返回原接纳回执；修改内容返回冲突。计划、容量预留、子实例组、事件同事务提交，任一角色非法或容量不足则全部回滚。
- 子实例组为 finite，TTL 30 分钟；父 Run 仍运行时不会派发子任务。父 Run 成功且子实例已准备好后，在同一事务将子任务插入原任务之前，原任务依赖这些子任务；原有下游继续依赖原任务。
- 父任务等待时不占用 Worker 槽位。续作使用原实际实例和会话、新 Run 与递增 Attempt generation；该任务的候选池固定为这个实例并切换为自动派发。原实例可用时才续作；若被终止/到期，则阻断。会话仍遵循普通实例的复用规则，等待期间不提供独占会话租约。
- 子任务继承父任务原有上游依赖，彼此独立；全部成功后原任务收到带 Run/实例/产物来源的贡献。子任务失败、取消或结果未知会阻断续作和下游，不用部分结果假装完成。
- 规划 Run 的成功文本保存在历史中，不发布为该 WorkItem 的最终产物；最终产物来自续作 Run。人工验收固定包括子任务在内的完整成果。
- 取消、失败和目标待验收都会回收本次委派拥有的实例组。取消不撤销外部效果。人工返工沿用已经展开的图、创建新的执行团队；已有委派任务不会再次提交计划，尚未委派的任务仍受原策略和累计上限约束。

## 崩溃与未知结果

schema v11 保存授权范围、不可变计划、预留子组和展开状态。重启发现来源 Run 已知成功时继续协调；已展开计划不会二次生成任务。来源执行中断、取消或效果未知时，放弃待展开计划并回收子组。即使委派工具曾返回成功，也不能把未知来源 Run 作为执行成功证据。

本实现不提供任意步骤的确定性重放、多机接管、执行后安全重试或工具副作用恰好一次保证。持久执行边界见 [Durable Workflow](durable-workflows.zh-CN.md)。

## API / CLI / MCP

使用现有 `POST /api/v1/goals`、`goals create`、`goals_create`，为任务添加 `delegation`。`POST /api/v1/research-jobs`、`research create`、`research_create` 接受顶层 `delegation`，应用到初始研究者任务，汇总任务保持直接整合。省略该字段保留原行为与旧请求幂等指纹。

```json
{
  "max_depth": 2,
  "max_children": 2,
  "max_descendants": 6,
  "roles": [
    {
      "name": "analyst",
      "preset_name": "demo-delegator",
      "preset_version": "1.0.0",
      "parameters": {}
    }
  ]
}
```

查询 Goal / Task 可读取 `delegation_scope` 和 `delegations`；后者包含来源 Run、原实例、计划状态、子任务、子实例组和续作要求。对外 MCP 工具数仍为 44 个，22 个只读。Agent 内部的委派插件与对外 MCP 操作者入口使用不同身份；没有接受任意 `source_run_id` 的对外写入口。

完整离线调研请求见 [delegated-research.json](../examples/clients/delegated-research.json)。

## 当前限制与验证

采用有界、追加式依赖展开：每个任务最多一次委派，无法随意删除/重排已运行任务，也没有跨目标子树迁移、自动模型路由、自动局部返工、团队费用预留和远程 Worker。工具能力由实际插件提供；`research-delegator` 默认没有网页检索工具。

原生集成测试覆盖来源成功门槛、不同实例、父级续作、下游等待、额度共享、深度上限、非法角色的整体回滚、并发幂等、取消竞争、子任务失败、未知结果恢复、已知成功恢复、不可变计划、真实 Demo Worker 的两层委派及返工、自主调研入口，以及 CLI/HTTP/MCP 读取同一谱系。

浏览器已从调研表单完成两层委派：4 位初始成员、12 位派生成员、15 项任务与 6 份委派计划；所有父任务使用原实例的新 Run 续作。1024/1440/1920 px 无页面横向溢出，Run 检查与 Escape 关闭正常，无脚本错误或 CSP 样式错误。

7333 上已用配置中的 OpenAI Responses / gpt-6-luna 完成真实模型链路：一个 Agent 主动委派给两个独立研究实例，再以新 Run 汇总，最终答案引用两个子 Run。该验证证明当前模型/插件/调度组合可以闭环，不代表任意任务都会主动分工，也不证明多机恢复或语义结论正确性。

独立验证 Agent 与授权整图自动返工已接入 Goal，可与委派组合；参见[验证指南](verification.zh-CN.md)。
