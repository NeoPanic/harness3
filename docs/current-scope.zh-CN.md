# 本地 P2：本轮交付范围

本轮优先补齐用户发起目标后，多 Agent 自主接续工作、交换发现并交付可追溯文件的主流链路。P1 作为现有控制面基础继续使用；P2 的完成条件收敛为下表三条必要闭环。完整架构仍见[目标设计](managed-agents.zh-CN.md)，逐项代码落点与验证状态见[实现进度](implementation-status.zh-CN.md)。

以下三条必要主路径已通过本轮集成验收。验证覆盖原生 Rust 测试、实际桌面 Web 与真实 OpenAI Responses 调用；仍不构成分布式、OS 隔离或任意调研质量保证。

| 必要闭环 | 可操作路径 | 本轮验收证据 |
| --- | --- | --- |
| 协作自主性 | Agent 查看任务板，追加研究任务或申请领取下一项工作；来源 Run 成功后控制面创建新任务/实例、更新尚未派发的直接下游依赖并继续调度 | 追加意图、来源 Run、任务图、Attempt 与后续产物可对应；验证器可按失败产物选择局部返工任务 |
| 协作空间 | 操作者建立同 Goal 频道与成员分组；Agent 读取/发言/订阅，新发言经持久消息唤醒订阅成员 | 非成员无法通过频道工具读取；一次发言只接纳一次通知，通知唤醒后的回复不继续广播 |
| 产物与工作区 | 每个实例写入自己的 UTF-8 文件，发布文件或 JSON 的不可变快照，同 Goal 成员读取，验证器检查冻结证据 | 修改源文件不改变快照；可追溯来源 Run、摘要和来源状态；新轮次只纳入当前任务及沿用成功任务的快照 |

自主任务追加限定为保留原图并补充依赖，不删除或改写已运行节点；任务领取沿用候选池及事务认领，不能强占他人正在执行的任务。局部返工根据验证器引用的失败产物定位任务。频道分组和共享上下文分别承担讨论与版本化事实，暂不自动裁决矛盾。文件快照进入证据清单后，验证器仍只能依据已有材料判断；通过 HTTP 插件取得外部文本不等于外部事实已获证明。

首次离线体验在“自主调研”选择 `demo-team@1.0.0`：实际读取任务板、发布频道发现、写入文件和 JSON 快照，并记录共享上下文。Demo 不执行自主追加，避免演示重复扩张；真实 Responses 调研可选择 `research-team@1.1.0`，是否追加由任务需要和实际模型工具调用决定。

绑定频道插件的任务参与者会自动加入“团队讨论”，订阅默认关闭；新增、委派和返工实例随参与关系加入，操作者显式移除的成员不会被协调器补回。

## 桌面导航与概念

导航从具体使用场景下钻到基础能力：**场景 → 协作 → 运行 → 配置**。“自主调研”放在场景组；目标、任务、频道和产物围绕协作展开；实例、执行记录和事件用于检查底层运行。Console 面向电脑使用，内容保持黑白灰，彩色品牌标识和连接状态承担少量颜色信息。

**Agent 池**是同一母体版本的一批实例及其期望数量，由控制面负责创建、补足、缩减和生命周期。它对应内部 `AgentFleet` / `/fleets`，不等同于一个协作团队。一个调研 Goal 可以用多个池的实例完成不同角色任务；手工创建池不会自动生成目标或团队协作。

## 本地运行边界

费用预算本轮不设团队硬上限，保留真实 usage 展示；不新增预算审批或费用预留要求。采用受信任本地工具与操作者权限，进程插件以 daemon 所在系统用户执行；当前没有多租户授权和 OS 沙箱承诺。文件工具自身保留相对路径及符号链接约束，避免把文件写入错误位置。

| 技术容量 | 当前默认值 |
| --- | --- |
| 活跃实例及待创建预留 | 256 |
| 本地 Worker 槽 | 8；同一实例串行 |
| 每个 Goal 的任务及待追加/待委派预留 | 64 |
| 递归委派深度 | 6 |
| 单次委派子任务 | 8 |
| 每根任务后代任务 | 48 |

这些是本机调度和输入规模约束，放宽数值不构成相应并发性能保证。协议请求长度、工具超时和模型上下文仍各有技术边界。

## 插件样例与后续范围

基本示例包括：[文本统计进程插件](../examples/plugins/text-inspector/)、[HTTP 文本读取进程插件](../examples/plugins/http-reader/)、[工作区母体与文件交接](../examples/plugins/workspace-preset/)。先覆盖安装、绑定、真实调用、文件/JSON 交付与跨 Agent 使用，不建设插件市场。

预算治理、细粒度权限、审批、执行隔离、通用任意图重写、自动冲突裁决、远程插件 loader、多机 Worker、发行与运维体验不作为本轮 P2 验收门槛。现有幂等、持久消息、取消和未知结果展示继续保留。复杂故障注入与同模型同预算的单/多 Agent 效果对照后置，当前先验证上述三条正常主路径。

功能契约见[自主任务板](autonomy.zh-CN.md)、[协作频道](channels.zh-CN.md)、[文件工作区](workspaces.zh-CN.md)和[验证与返工](verification.zh-CN.md)。

## 本轮验证记录（2026-10-28）

原生 Cargo check、Clippy、175 项 Rust 测试、rustdoc 与 quickstart 通过；HTTP 插件 4 项 Python fixture 测试通过。浏览器在 1024 / 1440 / 1920 px 检查主要页面和交互，无脚本错误。

离线 Demo 实际完成 3 项任务、3 条频道发言、6 份文件/JSON 快照；验证器冻结 9 份证据、通过验证并完成验收。真实 `gpt-6-luna` Responses 运行中，source 自主追加 `verify-source`，summary 等待二者完成，读取 2 份同伴快照，最终留下 3 份文件产物和 3 条频道发言。该记录证明追加、依赖协调与文件交接可以闭环，不能据此证明外部结论正确或协作收益优于单 Agent。
