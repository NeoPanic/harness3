# 自主调研 v1：一个目标到多 Agent 团队

普通 Run 是单 Agent 输入。**自主调研**是独立的平台用例：用户提交目标、验收标准、团队母体和研究者数量，平台自动创建实例、让模型规划分工、并行执行研究、传递贡献、汇总后等待人工验收。Web 首页提供“发起调研任务”，无需手工创建实例或填写任务图。

## 当前执行路径

1. 接纳事务同时保存 ResearchJob、幂等回执、finite 实例组和全部容量预留。团队数量为 `1 个规划 + N 个研究 + 1 个汇总`，N 为用户选择的 2–6。当前先创建完整有界团队，再规划任务；模型不决定初始数量；显式启用 `delegation` 后，研究者可在执行时继续受控派生。
2. 实例就绪后，平台保存角色、规划实例作为父级身份的成员关系，派发唯一规划 Run。所有实例继承用户所选的不可变 Preset 与参数，身份和会话相互独立。
3. 规划 Run 只注册第一方 `platform.research.plan` 工具，不注册研究者的外部工具。模型必须提交恰好 N 项不同分工和汇总要求；宿主选择执行实例和依赖关系，模型不能传入实例身份或调用无限 spawn。
4. 有效计划持久保存且不可覆盖。规划 Run 完成后，同一事务创建唯一 Goal 与任务图：N 项独立研究可并行，`synthesis` 等待所有研究成功，再收到其输出、实例 ID 与 Run ID。沿用全局 4 个 Worker 槽位和单实例串行约束。
5. 汇总完成进入待验收；用户核对结果后在同一 Goal 上验收。平台自动排空团队、关闭剩余槽位，保留实例、计划、Run、会话和贡献历史。验收结果同步到 ResearchJob。

这条链路已经提供任务驱动的有界团队派生与规划分工。[动态委派](dynamic-delegation.zh-CN.md)已支持批准角色范围内最多 3 层递归派生、追加子任务依赖与原研究者续作。无限层级、任意图重写、自主返工、独立验证器与预算账本仍待实现。

## 调研能力来自哪里

研究实例只能使用团队母体实际绑定的工具。平台不会因为任务叫“调研”就自动获得网页搜索、文件读取或数据库访问。绑定相关外部插件后才具备相应能力；没有检索工具时只能分析用户资料或模型已有知识，界面和任务指令均要求说明这个限制，禁止伪造实时检索与引用。

规划 Agent 可看到研究工具的名称与说明，从而按现有能力分工。规划阶段仅允许提交计划，不能调用这些外部工具。当前所有角色使用同一母体的模型协议/模型配置；推荐 OpenAI Responses，另外两种协议复用相同工具契约。Demo 只演示规划、并行和汇总的真实控制链路，不进行语义调研。

## 恢复、取消与上限

- 创建命令、容量预留和接纳回执同事务。相同 key/相同内容重试返回原对象，不重复创建团队；改内容复用 key 返回冲突。
- 计划与来源规划 Run 固定。重启保留已知 Harness 回执；规划执行结果未知时任务失败，不凭一份已保存计划继续派发。当前没有自动重试规划。
- 后续调度复用 Goal 的持久依赖、取消和恢复规则。研究失败、取消或中断会阻断汇总；工具回执中存在未知效果时，平台将该 Run 标为中断，即使模型已经生成答复也不会继续汇总；上下文超过 64,000 UTF-8 字节时明确阻断，不截断证据继续。
- 最多 8 项活动自主调研，仍受全局 64 个实例/预留容量及 32 个活动/待验收 Goal 上限约束。没有容量时整个创建事务回滚。
- 默认任务期限 15 分钟，团队实例 TTL 为 30 分钟的兜底。取消或到期停止后续派发，取消排队工作，请求活动 Run 协作停止，排空回收成员；已发生的工具效果不会撤销。
- 每个 Run 仍受 12 轮、24 次工具调用和 120 秒限制。当前没有团队费用预算预留，真实任务会产生规划、研究和汇总的多次模型调用费用。
- 初始团队角色关系为一层；动态子任务使用独立的 delegation_scope / delegations 追踪父任务、来源 Run 和深度。尚未提供通用主体授权和任意子树生命周期管理。当前没有不同任务间的公平性保证。

## 入口

| 操作 | HTTP | CLI | MCP |
| --- | --- | --- | --- |
| 提交 | `POST /api/v1/research-jobs` | `research create --file research.json --key KEY` | `research_create` |
| 列表 | `GET /api/v1/research-jobs` | `research list` | `research_list` |
| 详情 | `GET /api/v1/research-jobs/{id}` | `research show ID` | `research_show` |
| 取消 | `POST /api/v1/research-jobs/{id}/cancel` | `research cancel ID` | `research_cancel` |

请求示例见 [research.json](../examples/clients/research.json)，请换成实际已发布母体。HTTP 创建需要 `Idempotency-Key`，返回 202 接纳回执；MCP 写入口需要 `--allow-write`。详情包含规划 Run、分工、派生成员、Goal、各项研究贡献和最终汇总；Web 使用字段和任务列表展示，不展示原始 JSON。

Web **自主调研**与原有**协作目标**并存：前者自动创建团队与规划，后者让操作者显式编排已有实例。普通单实例运行继续保留。

## 人工评审与返工

待验收的调研可以要求修改，保留初始分工并创建新的研究者/汇总实例执行下一轮。平台继续使用同一个 Goal，将评审意见、各任务上一版文本和本轮依赖贡献传给新实例。最多 3 轮，完成后回收返工团队；旧 Run 与产物始终保留。详见[协作产物与返工](artifacts.zh-CN.md)。

## 中间发现与共享上下文

研究者可以通过显式绑定的 `platform.context` 发布和读取同目标发现，汇总实例收到派发快照并可主动刷新。平台不会广播私有会话或因发布记录自动创建任务；并发修订通过版本匹配处理。启动默认提供 `demo-collaborator`，Responses 就绪后提供 `research-collaborator`，Web 优先选用具备共享工具的 Responses 母体。来源、撤回和验收绑定见[共享上下文](shared-context.zh-CN.md)。
