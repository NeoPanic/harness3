# 自主调研：固定规划 / 研究 / 汇总模板

**自主调研**保留为显式选择的流程模板：用户提交目标、验收标准、团队母体和研究者数量，平台创建固定规划、研究和汇总实例，最后等待人工验收。该模板规定角色和初始数量；需要任务发布后按需选型、Agent 对等认领与拆分时，使用[共享任务板](task-board.zh-CN.md)。

## 执行路径

1. 接纳事务同时保存 ResearchJob、幂等回执、finite Agent 池和全部容量预留。团队数量为 `1 个规划 + N 个研究 + 1 个汇总`，N 为用户选择的 2–6。当前先创建完整有界团队，再规划任务；模型不决定初始数量；显式启用 `delegation` 后，研究者可在执行时继续受控派生。
2. 实例就绪后，平台保存角色、规划实例作为父级身份的成员关系，派发唯一规划 Run。所有实例继承用户所选的不可变 Preset 与参数，身份和会话相互独立。
3. 规划 Run 只注册第一方 `platform.research.plan` 工具，不注册研究者的外部工具。模型必须提交恰好 N 项不同分工和汇总要求；宿主选择执行实例和依赖关系，模型不能传入实例身份或调用无限 spawn。
4. 有效计划持久保存且不可覆盖。规划 Run 完成后，同一事务创建唯一 Goal 与任务图：N 项独立研究可并行，`synthesis` 等待所有研究成功，再收到其输出、实例 ID 与 Run ID。沿用全局 8 个 Worker 槽位和单实例串行约束。
5. 汇总完成后，有验证策略时先进入独立验证，否则直接待验收；用户核对结果后在同一 Goal 上验收。平台自动排空团队、关闭剩余槽位，保留实例、计划、Run、会话和贡献历史。验收结果同步到 ResearchJob。

团队可以组合[动态委派](dynamic-delegation.zh-CN.md)、[独立验证与局部修复](verification.zh-CN.md)、[自主任务追加与接续](autonomy.zh-CN.md)、[频道](channels.zh-CN.md)和[文件/JSON 产物](workspaces.zh-CN.md)。委派使用批准角色并支持原研究者续作；追加使用已发布的本地母体，在来源 Run 成功后创建新任务，并让尚未派发的直接下游等待新增贡献。

## 调研能力来自哪里

推荐使用 `demo-team@1.0.0` 离线体验，或在配置 Responses 后使用 `research-team@1.1.0`。团队母体绑定任务板、频道、共享上下文和文件工作区工具；Demo 实际调用这些工具并发布确定性演示内容，不自主追加任务。兼容的 `demo-collaborator`、`research-collaborator` 与委派母体仍可按需选择。

研究实例只能使用团队母体实际绑定的工具。网页搜索、数据库访问等能力需另外绑定外部插件；没有检索工具时只能分析用户资料或模型已有知识，应说明这个限制，不伪造实时检索与引用。

规划 Agent 可看到研究工具的名称与说明，从而按现有能力分工。规划阶段仅允许提交计划，不能调用这些外部工具。初始规划、研究和汇总使用同一母体的模型协议与配置；动态委派角色可以选择其他已发布母体。推荐 OpenAI Responses，另外两种协议复用相同工具契约。Demo 只演示规划、并行和汇总的真实控制链路，不进行语义调研。

## 恢复、取消与上限

- 创建命令、容量预留和接纳回执同事务。相同 key/相同内容重试返回原对象，不重复创建团队；改内容复用 key 返回冲突。
- 计划与来源规划 Run 固定。重启保留已知 Harness 回执；规划执行结果未知时任务失败，不凭一份已保存计划继续派发。当前没有自动重试规划。
- 后续调度复用 Goal 的持久依赖、取消和恢复规则。研究失败、取消或中断会阻断汇总；工具回执中存在未知效果时，平台将该 Run 标为中断，即使模型已经生成答复也不会继续汇总；上下文超过 64,000 UTF-8 字节时明确阻断，不截断证据继续。
- 最多 8 项活动自主调研，仍受全局 256 个实例/预留容量及 32 个活动/待验收 Goal 上限约束。没有容量时整个创建事务回滚。
- 默认任务期限 15 分钟，团队实例 TTL 为 30 分钟的兜底。取消或到期停止后续派发，取消排队工作，请求活动 Run 协作停止，排空回收成员；已发生的工具效果不会撤销。
- 每个 Run 受 12 轮、24 次工具调用和 120 秒限制。当前不设团队费用预算；真实任务会产生规划、研究和汇总的多次模型调用费用。
- 初始团队角色关系为一层；动态子任务使用独立的 delegation_scope / delegations 追踪父任务、来源 Run 和深度。尚未提供通用主体授权和任意子树生命周期管理。当前没有不同任务间的公平性保证。

## 入口

| 操作 | HTTP | CLI | MCP |
| --- | --- | --- | --- |
| 提交 | `POST /api/v1/research-jobs` | `research create --file research.json --key KEY` | `research_create` |
| 列表 | `GET /api/v1/research-jobs` | `research list` | `research_list` |
| 详情 | `GET /api/v1/research-jobs/{id}` | `research show ID` | `research_show` |
| 取消 | `POST /api/v1/research-jobs/{id}/cancel` | `research cancel ID` | `research_cancel` |

请求示例见 [research.json](../examples/clients/research.json)。体验完整团队工具时，将母体设为 `demo-team@1.0.0` 或 `research-team@1.1.0`。HTTP 创建需要 `Idempotency-Key`，返回 202 接纳回执；MCP 写入口需要 `--allow-write`。详情包含规划 Run、分工、派生成员、Goal、各项研究贡献和最终汇总。

Web 的“自主调研”与“协作目标”并存：前者自动创建团队与规划，后者让操作者显式编排已有实例。普通单实例运行继续保留。

## 人工评审与返工

待验收的调研可以要求修改，保留初始分工并创建新的研究者/汇总实例执行下一轮。平台继续使用同一个 Goal，将评审意见、各任务上一版文本和本轮依赖贡献传给新实例。最多 3 轮，完成后回收返工团队；旧 Run 与产物始终保留。详见[协作产物与返工](artifacts.zh-CN.md)。

## 中间发现与共享上下文

研究者通过 `platform.context` 发布和读取同目标发现，汇总实例收到派发快照并可主动刷新。平台不广播私有会话；并发修订通过版本匹配处理。频道用于讨论与显式订阅唤醒，工作区快照用于共享文件和结构化资料；共享上下文保留可修订的发现与决策。来源、撤回和验收绑定见[共享上下文](shared-context.zh-CN.md)。
